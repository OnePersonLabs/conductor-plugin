# Propose the next change

Follow [repository scope](../../references/repository-scope.md) and
[issue context](../../references/issue-context.md). Use an explicit issue, the
established current issue or the user's direct local request. For a requested new
named issue, compose $conductor:new-change, then $conductor:plan-change. For an
existing issue or local request, plan against that existing owner.

Investigate the intended outcome, accepted constraints and relevant source.
Develop a complete next-phase proposal while keeping future phases broad. Follow
[phase artifacts](../../references/phase-artifacts.md) when saving an authorized
tracked plan. The coordinator owns saving artifacts and GitHub writes; bounded
delegates return content and evidence.

A proposal-only request ends with the proposal, its evidence, assumptions and
decisions that remain with the user. Planning does not mark work ready, accept a
new product direction, release holds or grant execution authority. State which
scope is already authorized and which remains proposed. Stop before
implementation, publication or automatic continuation.
